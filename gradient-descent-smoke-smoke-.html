What is gradient descent and why does it matter?

You have a function and you want to find its minimum. In machine learning, that function is the loss — a measure of how wrong your model's predictions are. The minimum corresponds to the model parameters that make the best predictions. But for most real models, there is no closed-form solution. You cannot just solve an equation. You need an iterative method. Gradient descent is that method. It works by repeatedly taking small steps downhill, guided by the slope (gradient) of the loss function at the current point. The core idea is simple: if you know which direction is downhill, walk that way. The problem it solves is optimization at scale — millions of parameters, billions of data points. Without gradient descent, training neural networks would be computationally infeasible. It is the engine behind almost every modern ML model.

How it works

Gradient Descent

Gradient descent is a first-order iterative optimization algorithm. It uses the gradient of the loss function with respect to the model parameters to update those parameters in the direction of steepest descent. The update rule is: θ = θ - η * ∇_θ J(θ), where θ is the parameter vector, η is the learning rate (a positive scalar), and ∇_θ J(θ) is the gradient of the loss function J with respect to θ. The gradient points in the direction of greatest increase, so subtracting it moves downhill.

The algorithm has three main variants: batch, stochastic, and mini-batch. Batch gradient descent computes the gradient over the entire training set. It is deterministic but slow for large datasets. Stochastic gradient descent (SGD) computes the gradient on a single randomly chosen example. It is fast per update but noisy — the loss bounces around. Mini-batch gradient descent is the practical compromise: compute the gradient on a small random subset (e.g., 32 or 256 examples). It balances speed and stability.

Failure modes are common. A learning rate that is too high causes divergence — the parameters overshoot the minimum and the loss increases. A learning rate that is too low makes convergence painfully slow. The algorithm can also get stuck in local minima or saddle points, especially for non-convex loss functions like those in deep neural networks. In practice, saddle points are more problematic than local minima because gradients near saddle points are very small, stalling progress.

Momentum is a common fix. It adds a fraction of the previous update to the current one: v = γv + η∇_θ J(θ), θ = θ - v. This helps the optimizer accelerate through shallow valleys and dampen oscillations. Adaptive methods like Adam (Adaptive Moment Estimation) adjust the learning rate per parameter using estimates of first and second moments of the gradients. Adam is the default choice for most deep learning tasks because it handles sparse gradients and noisy data well.

Real tradeoffs: batch size affects generalization. Small batches add noise that can help escape sharp minima, often leading to better generalization. Large batches give more accurate gradient estimates but may converge to sharp minima that generalize poorly. Learning rate schedules (decaying η over time) are often necessary for fine convergence.

Important: The choice of learning rate and batch size are critical hyperparameters that directly impact convergence and generalization performance.

In practice

python
import numpy as np

# Simple linear regression: y = wx + b
# Loss: mean squared error

def mse_loss(y_true, y_pred):
    return np.mean((y_true - y_pred) ** 2)

def gradient_descent(x, y, w, b, lr, epochs):
    n = len(x)
    for epoch in range(epochs):
        y_pred = w * x + b
        # Gradients
        dw = (-2 / n) * np.sum(x * (y - y_pred))
        db = (-2 / n) * np.sum(y - y_pred)
        # Update
        w -= lr * dw
        b -= lr * db
        if epoch % 100 == 0:
            loss = mse_loss(y, y_pred)
            print(f"Epoch {epoch}: loss={loss:.4f}, w={w:.4f}, b={b:.4f}")
    return w, b

# Generate synthetic data
np.random.seed(42)
x = np.linspace(0, 10, 100)
y = 2.5 * x + 1.0 + np.random.normal(0, 1, 100)

# Initialize
w, b = 0.0, 0.0
lr = 0.01
epochs = 1000

w_opt, b_opt = gradient_descent(x, y, w, b, lr, epochs)
print(f"Optimized: w={w_opt:.4f}, b={b_opt:.4f}")
